Tracker Data Disclosure

Last updated: August 15, 2026

This page discloses every piece of data collected by the Storecops storefront tracker script (tracker.js). This disclosure is provided for Shopify app review compliance, GDPR/CCPA transparency, and merchant awareness.

1. How the Tracker is Installed

The tracker is injected into merchant storefronts via the Shopify Script Tag API (or manually pasted before </body>). It loads from the Storecops platform server and communicates exclusively with the platform's /api/v1/track endpoint using a write-only ingest key.

2. Identifiers

IdentifierStoragePurposeLifetime
visitor_idlocalStorage (sc_vid)Links behavioral events across pages for the same visitorPersistent until browser clear

Neither identifier contains PII. Both are random UUIDs generated client-side. No cookies are used.

3. Events Collected

Event TypeTriggerConsent RequiredData Sent
session_start Page load (once per session) Analytics store_id, event_type, timestamp, visitor_id, session_id
product_view Visiting a product page (auto-detected or via Storecops.view()) Analytics product_id, product_price, page_url
cart_updated Adding/updating cart (AJAX interception or Storecops.cart()) Marketing product_id, quantity (if provided)
cart_abandoned Mouse-leave exit intent or Storecops.abandon() Marketing exit_intent flag, product_id (if provided)
purchase Merchant calls Storecops.purchase(order) Marketing Order data as provided by merchant (customer_id, total, items)
lead_captured Email typed into a form field (detected on blur) Marketing email address
scroll_depth Scrolling past 50%, 75%, 90% of page Analytics depth percentage

5. Data NOT Collected

  • No IP address — the tracker does not read or send the visitor's IP.
  • No user-agent string — browser/OS info is not collected.
  • No cookies — only localStorage and sessionStorage are used.
  • No full page HTML/DOM — only specific meta tag values are read.
  • No cross-site tracking — identifiers are scoped to the merchant's domain.
  • No fingerprinting — no canvas, WebGL, font, or screen resolution data.

6. Consent Gating

The tracker enforces a two-tier consent model:

  • Analytics events (session_start, product_view, scroll_depth): Sent only when analytics consent is granted. On Shopify stores, this reads from the Shopify Customer Privacy API (window.Shopify.customerPrivacy.analyticsProcessingAllowed). Default (no consent banner): allowed.
  • Marketing events (cart_updated, cart_abandoned, purchase, lead_captured): Sent only when marketing consent is granted. Reads from window.Shopify.customerPrivacy.marketingAllowed. Default (no consent banner): blocked.
Before any consent signal exists, only anonymous analytics events are sent. Marketing events (including cart activity and email capture) are blocked until explicit opt-in. Merchants can override via window.STORECOPS_CONSENT = "granted" | "denied".

7. Consent Change Listeners

The tracker listens for runtime consent changes via:

  • tracking_consent event (Shopify Customer Privacy API)
  • cmp:consentupdate event (Google Consent Mode v2)
  • storecops:consent event (merchant custom banner)

When consent is newly granted, tracking begins. When consent is revoked, all transmission stops immediately.

8. Data Transmission

  • Endpoint: POST /api/v1/track on the Storecops platform server.
  • Authentication: Write-only ingest key (passed as ?api_key= query param or X-API-Key header). This key can only write events — it cannot read any data.
  • Method: Uses navigator.sendBeacon() when available (survives page unload), falls back to fetch() with keepalive: true.
  • Rate limiting: Maximum one transmission per 1.5 seconds to prevent excessive network usage.

9. Merchant API

Merchants can programmatically trigger events via the global window.Storecops object:
